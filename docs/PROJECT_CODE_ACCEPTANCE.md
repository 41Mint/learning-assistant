# 项目代码 v1 验收指南

在 [本地学习助手](http://localhost:5185/) 验收。以 Whack-a-Mole 的 `Assets/Scripts/InputManager.cs` 为例，也可以换成另一份 UTF-8 的 `.cs` 文件。单个脚本可保存至 512 KB。

1. **保存本地快照。** 在“今日学习”或一篇已有的历史日志展开“项目代码”，点“添加代码版本”。新项目填 `Whack-a-Mole`，选中 Unity 项目内的 `InputManager.cs`，项目内路径填 `Assets/Scripts/InputManager.cs`，说明填“本地快照”。保存后打开脚本链接，确认代码高亮显示，并能从“引用记录”回到这篇日志。
2. **在原项目保存 GitHub 版本。** 在已登录的 GitHub 文件页选定一个提交，按 `y` 后复制地址。回到日志再次点“添加代码版本”，选择原项目，粘贴“GitHub 固定链接”，说明填“已提交版本”，文件留空。保存后应在同一项目下看到两个版本。先试一个带分支名的文件地址，可以看到需要固定提交链接的提示。
3. **检查私有仓库跳转。** 打开第二个版本，点击“在 GitHub 查看此版本”，用有权限的账号确认打开对应文件与提交。返回第一个版本，检查本地脚本仍可读。也可在本地快照的“编辑版本资料”中补上与该文本对应的固定链接。
4. **关联词条和单次实践。** 编辑任一词条，在“关联资料（可选）”中展开“关联代码版本”，勾选第一个版本并保存。阅读时从“项目用例”打开。在“成长记录”中创建或编辑一次实践，用同样的方式勾选第二个版本并保存。回到两个代码详情，确认“引用记录”分别指向正确的词条和实践。
5. **备份与恢复。** 在“数据管理”导出完整备份，到 Edge InPrivate 窗口访问同一地址并恢复文件。摘要应列出项目、版本和关联数。恢复后从原日志或实践打开代码，检查本地文本、固定链接和回链。浏览器打开私有 GitHub 文件时使用该窗口已登录的账号。

完整备份保存本地快照的脚本文本。仅链接的版本在备份里保留链接，查看源码仍由 GitHub 页面提供。v1 至 v4 的旧备份可以恢复对应资料，确认摘要会提示其中缺少项目代码。

已有代码关联会在编辑实践时预选。可取消勾选后点“取消”检查原关联，再重复操作并保存，确认代码链接已从该次实践移除。编辑时其他成长卡片收起，滚动表单仍可找到底部操作区。

## 项目目录导入 v1

1. 打开[项目代码](http://localhost:5185/#code)，点“导入项目目录”。选择 Whack-a-Mole 的项目根目录 `D:\UnityProject\Whack a Mole`。浏览器枚举大目录时可能需要等待。预览应显示 `Assets`、`Packages` 和 `ProjectSettings`，跳过顶层 `Library`、`Builds` 等缓存或构建目录和 `.meta` 文件。
2. 展开 `Assets/Scripts`，勾选 `InputManager.cs` 和 `GameManager.cs`，选择新建项目或已有的 Whack-a-Mole 项目，点“保存目录快照”。可以只保存目录，之后通过“更新目录快照”再补选脚本。
3. 打开保存后的目录树，点击 `Assets/Scripts` 的名称，为它填职责说明并保存。再点击 `InputManager.cs`，填写该文件的职责，打开其中一个版本核对正文。从一篇日志的“项目代码”关联这个已有版本，再在代码详情中核对日志回链。
4. 在项目卡片点“更新目录快照”，重新选择同一目录与同一脚本。未变化的脚本应复用最新本地版本。刷新页面后，检查目录、职责说明和日志关联仍在。
5. 导出完整备份，在独立的 Edge InPrivate 窗口检查恢复摘要。恢复后，从目录树打开脚本，核对职责说明和版本链接。

每个项目保存最新一份目录快照。快照只含浏览器返回的相对路径，因此空目录不会出现在树里。未勾选的文件只保存路径。更新快照时，仍存在的路径保留说明。脚本版本和学习资料关联独立保留。

「添加代码版本」和「导入项目目录」在项目代码页原位展开，取消后收起并将焦点交还原按钮。项目卡片的「导入目录」和「更新目录快照」也可直接在卡片内操作。

## 代码版本回收站

1. 打开一个有关联资料的测试代码版本，点「删除代码版本」，再点「移入回收站」。检查同项目的其他版本仍可打开。
2. 到「数据管理」，在回收站顶部切换「日志」「词条」「代码」。在「代码」中按项目、路径和保存时间找到测试版本。点「恢复代码版本」并确认，从恢复提示打开原版本，核对脚本文本、版本说明、固定链接和引用记录。
3. 再次将测试版本移入回收站。导出完整备份，在独立的无痕窗口恢复。切到「代码」，恢复测试版本并核对原关联。若同路径还有较新的版本，检查项目目录仍优先展示较新版本。
4. 用测试版本验证「彻底删除」。确认后在日志、词条和实践中检查相关链接已移除，同项目其他版本仍可打开。
5. 将测试项目的所有代码版本移入回收站，从项目卡片点「删除项目」。先取消，核对卡片仍在，再确认删除。刷新后项目应从列表和项目选择框中移除。从回收站恢复任一版本，核对项目、目录快照和关联一同恢复。已从列表删除的项目，在回收站中最后一个版本被彻底删除时会一并清理。
